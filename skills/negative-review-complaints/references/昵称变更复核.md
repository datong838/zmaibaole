# 昵称冲突只读复核

`case_alias_cli.py` 是独立入口；普通 Excel/页面昵称精确匹配不放宽。只查看已有投诉结果，无投诉提交、截图、发送或原台账写入。

使用项目日统 venv 运行：

```
case_alias_cli.py prepare --order ABS --order-sha256 SHA --lease ABS --lease-sha256 SHA
case_alias_cli.py run --manifest ABS --manifest-sha256 SHA --steps 10
case_alias_cli.py reconcile --manifest ABS --manifest-sha256 SHA --original-state-sha256 SHA
case_alias_cli.py verify --manifest ABS --manifest-sha256 SHA
case_alias_cli.py record-reconciled --manifest ABS --manifest-sha256 SHA
```

订单固定字段：`kind=unbound-complaint-case-read-order-v1`、`manifest`、`actions=[complaint-read:open,complaint-read:close]`、`never=[complaint,submit,capture,send,record_result,case_memory]`、`person_identity_verified=false`。
manifest 固定字段：`kind=unbound-case-inspection-manifest-v1`、原 `root/review_key`、`inputs`、`old_result/old_drawer`、完整相关 `pending_drawers` 映射、`legacy_operations`。
inputs 九项为 `ledger/old_job/old_source/old_envelope/old_profile/old_orders/fresh_job/fresh_profile/normal_before`；全部输入用绝对路径与 SHA256 引用。prepare 纯校验后给出唯一 canonical manifest；后续复用其原路径、原 SHA。

仅公开投诉类型、精确投诉时间、完整理由，以及门店、评价全文、完整商品和评分逐项一致且范围内一对一唯一，才生成独立 alias 收据。证明投诉记录关联，不证明人的身份；原 source、key、customer 与 case_id 保留。未知效果只能显式只读 reconcile；不能重开、换 key 或放开截图权限。当前仅支持已见一星及完整商品叶结构，其他结构保留待核。

收据通过后运行 `scripts/apply_case_alias.py --receipt ABS --receipt-sha256 SHA`，仅写原任务结果、追加同一案例的新观察并重建Excel；旧结果完整归档，同收据重复执行不新增事件、不重复导出。导出失败保留已写JSON，下次仅补导出。当前 canonical 操作仅支持首次关联，次日须新复查能力验收后再启用，不能复用旧观察冒称今日结果。
