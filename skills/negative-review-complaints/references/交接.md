# 命令与数据

以下均从项目根目录运行。`--root` 必须为固定公司目录，例如 `runtime/negative-review-complaints/上海老芗汇餐饮管理有限公司`。首次范围默认前一个工作日至昨天；只有明确补做需求才给 `init --start YYYY-MM-DD`。日历不覆盖的年份先更新共享日历，不静默猜日期。

```sh
python3 skills/negative-review-complaints/scripts/workflow.py --root runtime/negative-review-complaints/上海老芗汇餐饮管理有限公司 init --company 上海老芗汇餐饮管理有限公司 --groupid 1764303851132943
python3 skills/negative-review-complaints/scripts/workflow.py --root runtime/negative-review-complaints/上海老芗汇餐饮管理有限公司 plan
```

Excel运行依赖已安装Codex捆绑运行时。脚本目录中的 `node_modules` 链接指向 `~/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules`；迁移后重新建立链接。无需新Chrome扩展、开发者模式、调试服务或新API密钥。企业微信沿用发送岗已验证的macOS辅助功能权限。

| 命令 | 参数 | 作用 |
|---|---|---|
| capture | --input capture.json | 验收完整筛选列表 |
| screenshot | --id GROUP:ID --file 实际截图.png --metadata screenshot.json | 截图绑定页面证据 |
| send-order | --id GROUP:ID | 只读查看唯一发送工单 |
| send-test | --id GROUP:ID | 真正向测试群发送截图附件，保存发送岗原始回执 |
| wecom | --id GROUP:ID --input 原始发送岗状态.json | 已由发送岗执行时导入回执 |
| analysis-order | --id GROUP:ID | 给AI的原文、判断约束与输入字段 |
| history | --id GROUP:ID --input history.json | 登记近7天其他类投诉记录 |
| analyze | --id GROUP:ID --input analysis.json | 保存判断及草稿，不提交 |
| result | --id GROUP:ID --input result.json | 已有投诉结果复查 |
| block | --id GROUP:ID --reason 原因 | 记录停点；复核后重新登记有效证据 |
| close | --batch START_END-EXCLUSIVE | 校验并完成草稿批次 |
| export / status | 无 | 修复Excel导出 / 查看并刷新汇总 |

JSON字段均为数据。证据复制到工作目录，按内容哈希存放。结构定义以 `workflow.py` 校验为准。

`capture.json`：account_verified=true、identity（provider/account_id/manager，来自采集岗身份核验，首次固定后不允许变化）、source=`codex-existing-extension`、company、groupid、url（真实当前页面）、start、end_exclusive、observed_at（带时区）、negative_filter=`中差评（1-3心）`、filter_active=true、other_filters（评价类型/来源/状态均全部）、fold_boundary_verified=true、all_pages_read=true、filtered_count、rows。

rows：review_id（平台稳定ID，不以昵称代替）、section=`filtered`、store、customer、customer_id（可选）、date、time（可选）、stars、text、product、action（投诉/查看投诉结果）。folded记录被丢弃；采集器直接不读其内容。多页必须完整读取并核对计数，未支持的分页不能假报完整。

`screenshot.json` 正式模式固定字段：`review_key`、`snapshot_sha256`（当前账本capture原始字节哈希）、`source=local-dom-bridge`、`sha256`（实际PNG哈希）、`registration={path:绝对路径,sha256:注册文件哈希}`。registration由独立 `chrome-dom-export/scripts/review_capture.py` 生成，投诉岗调用 `review_registration.validate` 重验本次源/身份/正常区/canonical/前后DOM与PNG授权链；每次send-order再次验证。`filters_visible/review_visible=true`不能替代链。正文收起可如实 `text_complete_in_image=false`，遮挡未验真时保持 `occlusion_verified=false`，不伪称全文或无遮挡。开发群固定“测试群请忽略”。fixture才允许旧模拟布尔字段，禁止外发。

`history.json`：company、groupid、url、source、observed_at、start（执行日减7天）、end_exclusive（执行日）、all_pages_read=true、items。items每条含date、category=`其他`、text（可见完整投诉内容）。完整查询为空可记items=[]；查询失败不能记零。只参考措辞，不照抄本条未证实的事实。

`analysis.json`：见analysis-order的analysis_fields。category四选一；quotes必须逐字来自原文；疑似批量需related_ids、同日同名且similarity_reason，identity_uncertain=true。其他需history_sha256。agent_assessed及no_fabricated_facts必须true；这是AI责任声明，代码不冒充语义真实性证明。

`result.json`：review_key、snapshot_sha256、url、source、observed_at、status（pending/accepted/rejected/unknown）、visible_text（平台结果原文）。只有accepted/rejected结案；unknown不结案。不能根据截图上的「查看投诉结果」推断已通过。

正式记录不接受fixture输入；测试用 `init --mode fixture`，必须使用独立测试目录，且禁止外发。`--today`仅用于离线日期测试，正式采集证据仍必须为当天。

## 本地DOM桥输入（未真机验收）

独立目录初始化可选 `init --backend local-dom-bridge`；来源在首次初始化固定，不允许将本地桥凭据标成现有Codex连接，也不迁移已有完成记录。其截图、历史、结果的source均须相同。fixture仍只接受fixture且禁止外发。

`semantic-intake.mjs` 的 `intakeReviewTree(observation, job, profile)` 只处理JSON树，不调用浏览器或执行脚本。observation包含source、tab_id、tab（枚举所得id及完整url）、observed_at、tree（桥实际返回的kind/url/root/truncated）。profile沿用字段名，定位值为桥返回的完整selector或严格role/name/attributes匹配对象；otherFilters指定三项筛选器。读取日期须datetime或绝对日期，星级须data-rating/明确无歧义文本；不得从心形像素或相对日期猜测。仅完整、非截断、全部正常区行数对齐才产出capture；否则返回gaps，不能填true绕过。聚合容器name不读取，折叠子树不下降。profile仍保持awaiting-live-validation；mock通过不构成真机验收。

空账本补做起点修正：`amend-empty-start --start YYYY-MM-DD`。仅允许尚无任务、批次、完成、发送、覆盖进度或业务历史的账本将起始日提前；必须早于旧起点及今天。代码保留旧state原字节备份和SHA256审计，不能清空既有处理记录来绕过。已有处理一律拒绝。本入口不会执行采集、发送或把任何日期记为完成。

旧版空账本切换已批准连接：`amend-empty-backend --backend local-dom-bridge`。与空起点修正共用严格未处理门槛，额外要求尚无任何已核身份；保留原state字节备份/哈希和审计，不能迁移已有任务、发送或覆盖进度。可以先amend起点再amend连接，顺序可审计。实际账本仅由执行岗按工单操作。

进入待校准中差评页面的固定准备入口：`bridge-navigation.py --receipt 当前采集岗收据 --receipt-sha256 实际哈希 --source-work-order-id 当前工单ID --prepare-job 新导航工单.json`，仅从本次已核Excel收据生成导航数据。获Chrome时隙后以 `--job 导航工单.json --tab-id 实际评价页ID --state 固定导航状态.json` 每次tick；共享已验收身份/日期纯DOM函数，按已观察未选中样式点击中差评后停在profileRequired，保存实际树。此入口不登记评价/完成、不发群、不提交投诉。实际normal/fold/分页/原文/结果及历史profile仍须真机校准；不得把导航停点当投诉验收。

纯文件正常区适配入口：`normal_observation.py --job 固定导航job.json --envelope 真实分页树envelope.json --profile 本公司已核profile.json --profile-sha256 实际哈希 --receipt 本次operator-acquisition.json --receipt-sha256 实际哈希 --out 不存在的新capture.json`。profile必须为本公司、已核正常区结构；未验收直接拒绝。只精确匹配公开leaf全文，压缩空白/截断/歧义拒绝；canonical、日期和星级由本次真实Excel唯一匹配补齐。审核中也是既有投诉，仅结果复查，不进入新草稿。
