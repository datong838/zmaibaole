# 采集入口

默认后端为 `local-dom-bridge`，依赖已有 `../chrome-dom-export`。枚举已有标签后，将明确目标ID传给 `role_cli.py prepare --work-order ... --tab-id ...`，执行返回的 `tick_argv`。CLI不自动选择标签、不安装扩展、不改权限。

`bridge-workflow.py --work-order ... --tab-id ...` 默认一步，可用 `--steps 1..25`；`--status`不推进。批量遇等待或 `*ProfileRequired` 停点即停；经核实后明确单步恢复。错误、身份差异或未知操作结果交监理修代码、重派原工单，不清日志、不盲点。监督岗不代替执行岗操作。

正式 `workflow.json` 绑定工单指纹并持有单写者锁。导出/下载先落意图；未知导出只对照记录差集，未知下载只续查原票据。文件必须由真实下载结果与XLSX校验产生。编排岗自动调用 `role_cli.py finalize --work-order ... --journal ... --out ...`；不能用手填candidate替代。

连接跨后端恢复必须有明确恢复工单且无导出/下载意图，保留旧日志。旧Codex收据与显式旧入口保留兼容，不作为自动备用路线。

原生外壳恢复只用代码核验的Chrome工具栏：[弹窗恢复](外壳弹窗恢复.md)。扩展维护入口为 `chrome-maintenance-control.py --open-maintenance-control --expected-pid ... --out ...`，只在已授权维护时用；既有意图不重放，工具栏返回不等于控制页已加载。

离线验证：`python3 -m unittest discover -s tests -q`。模拟测试不等于真机验收。

跨品牌业务岗先用 `prepare_company_navigation.py --help` 的离线入口生成独立公司导航工单：显式真实采集收据及哈希、已核registry或两公司收据及哈希、目标公司/ID、独立绝对outdir、purpose和stable-key。输入保存原字节快照；同绑定复用、哈希或身份冲突拒绝。返回prepare_argv仍须追加真实标签ID；只完成身份/公司导航，不改原日统日志、不导出、不发群、不推进日期。
