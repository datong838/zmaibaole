# 运行入口

命令从本skill目录运行；安装见SKILL.md。公司顺序与群映射只读 `config/company_wecom_map.csv`，groupid配置在 `config/companies.json`；2026节假日和补班日在 `config/holidays.json`，缺年份会警告并标复核。

```sh
.venv/bin/python scripts/flow.py init
.venv/bin/python scripts/flow.py advance --run-dir /init输出的run_dir
```

advance产生的工单已落盘，交采集岗执行即可；采集完成或失败后再advance。检查点导入、文件验收、统计、下一家及返回首家公司均由代码推进。

补跑、目录覆盖：

```sh
.venv/bin/python scripts/flow.py init --start 2026-10-16 --end 2026-10-18 --outdir /批次目录 --export-dir /原始文件根目录
```

默认用上海时间，首次上个工作日到昨天，两端包含；以后按公司从连续完成截止日的下一天补到昨天。非工作日跳过，`--force`可强制。自动批次落在 `work/<运行日>/daily/<序号_公司>/`，手动日期批次在 `work/<运行日>/<起>至<止>/<序号_公司>/`，原始文件在 `runtime/exports/<序号_公司>/`。工单及浏览器日志在公司目录的operator/return下，各批次独立。

停止与恢复：

```sh
.venv/bin/python scripts/flow.py status --run-dir /批次目录
.venv/bin/python scripts/flow.py repair --run-dir /批次目录 --company '公司名'
.venv/bin/python scripts/flow.py resume --run-dir /批次目录
```

repair优先用已有原始文件修复产物。resume仅解除编排停批，不修复连接或登录，不清除采集日志失败。身份/风控/连接问题需先处理真实原因；未知导出和下载不得清日志重跑。`init --rerun`也会拒绝丢弃未解决的任务。低层checkpoint/record-source只供维护与测试，日常执行不手填。

纯文件统计：

```sh
.venv/bin/python scripts/run.py --src /原始.xlsx --company '公司名' --start 2026-10-16 --end 2026-10-18
.venv/bin/python scripts/batch_run.py --src-dir /原始文件目录 --start 2026-10-16 --end 2026-10-18
```

无实时来源证据的人工导入标needs_review；不冒充正式采集。零条仅收据，非零产明细、统计和映射；明细保留原始字节。发送始终禁用。

测试：`.venv/bin/python -m unittest discover -s tests -q`。真机验收范围见验收报告。

测试群日报文字由 `scripts/render_update.py` 从原始Excel计算，支持每日/门店汇总及中差评原文；截图只参考版式。参数见--help，输出仅测试文本，不发送。

日报正文不附数据说明。`--format online`省略测试提示及拟发群，仅生成文案，不放行发送。本工作流只包含评价统计、评价详情及商家回复状态；投诉和违规均不采集、不处理、不在消息中展示。

进度用 `flow.py progress` 查看，默认台账为项目 `runtime/daily-comment-stats/progress.json`；init可用--progress-file指定，但跨日必须沿用同一台账。初始未完成日期可用 `flow.py progress --company '公司名' --initial-start YYYY-MM-DD`声明一次；不会写成已完成，也不能覆盖旧进度。

各公司工单date_range是实际采集范围，批次date_range为它们的合并范围。完成日期last_completed_on与数据截止日covered_through分别记录。仅正式核验成功（含0条）推进，失败/待复核/演练不推进；手工补跑须连上已覆盖区间才能推进，不跨过空缺。未知导出或未处理的原始文件留在旧批次时，先恢复旧批次，禁止另建重复导出。纯文件run.py/batch_run.py不更新正式台账；发送状态也不与数据进度混淆。
