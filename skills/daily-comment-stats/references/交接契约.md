# JSON交接

两个岗位不跨目录导入实现。执行入口为 `flow.py advance` 与采集岗 `createWorkflow(...).tick()`。

| 文件 | 生产者 | 消费者 |
|---|---|---|
| work-order.json | flow.dispatch | 采集岗prepare/createWorkflow |
| workflow.json | workflow-runtime | flow.sync_operator、采集岗finalize |
| acquisition.json | 采集岗finalize | flow.record_source、统计处理器 |
| receipt.json | ds_processor | flow.next_task |
| batch_receipt.json | flow.save | 编排与复核 |

工单绑定work_order_id、公司、groupid、日期、账号基线、日志与原始文件目录。日志绑定工单，包含唯一event_id、固定阶段、意图、生成记录及下载结果。advance按event_id幂等导入，检查顺序后调用独立CLI验收；正式工单不接受手填candidate。

权威字段及校验以代码为准：`flow.py`、采集岗 `workflow-runtime.mjs` 和 `role_cli.py`。不要从文档重建状态机或补写成功收据。收据是本地执行证据，非平台签名。

跨日进度由ds_progress.py管理，各家公司工单携带自己的date_range。正式收据校验成功后才记连续覆盖区间；消息发送回执不代替数据完成证明。
