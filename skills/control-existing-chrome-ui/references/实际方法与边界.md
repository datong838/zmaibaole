# 真实方法与接收方交接

## 这次改正了什么

用户要求封装实际操作方法，不要求另写浏览器实现；用户账号不能使用 Chrome 开发者模式。

此前新写的 `chrome-dom-export` 并非实际操作时使用的工具，现已从活动 skills 目录移到 `work/superseded/`，作为作废归档保留。新版不依赖那套扩展、Python HTTP 服务、回环密钥或安装步骤，也没有向用户当前 Chrome 安装过它。

新版复用当前 Codex 已暴露的 `mcp__cua_repl.js` 工具。安装 skill 只复制说明和运行时调用辅助文件，**不会新增 Chrome 能力**。

## 会话中确实出现过的调用

```javascript
await cua.getState();
```

返回 Chrome 连接类型 `extension`、已打开的抖音来客标签；最初另有 ChatGPT 标签，用户关闭后只剩抖音来客。该列表证明已有连接，不能证明它由谁安装，不能证明无调试。

最初 `cua.getTab(...)` 连续超时；随后一次报告 `Debugger unattached`。之后实际取得 DOM 的方式是：

```javascript
var browser = await cua.getBrowser({id:'1'});
await browser.nameSession('🔎 来客评价统计');
nodeRepl.write(await browser.user.openTabs());
var liveTab = await browser.user.claimTab('995697443');
nodeRepl.write(await liveTab.playwright.domSnapshot());
```

这里的 ID 是历史记录，不能作为下次运行的常量。后来内核超时重置时也用过 `browser.tabs.get(...)` 重新取得句柄；这不能作为遇到 debugger 错误继续重试的理由。

实际点击使用过：

```javascript
await liveTab.playwright.getByText('全部评价 4367',{exact:true}).click({timeoutMs:5000});
await liveTab.playwright.getByRole('textbox',{name:'评价时间',exact:true}).click({timeoutMs:5000});
await liveTab.playwright.getByRole('button',{name:'切换公司',exact:true}).click();
await liveTab.playwright.getByPlaceholder('搜索商户',{exact:true}).fill('烟台一成');
await liveTab.playwright.getByText('导出评价',{exact:true}).click();
nodeRepl.write(await liveTab.playwright.domSnapshot());
```

这些是会话摘录，不是盲执行脚本。日期曾通过 DOM 中九月/十月上下文和文本定位；不能泛化为“日期一律点最后一个”。页面异步更新，有时点击后第一次快照仍是旧状态；须核验实际结果，不自动重复点击。

曾读取 DOM 元素属性来辨别控件：`locator.evaluate(...)`、`evaluateAll(...)`。本 skill 的默认辅助函数不暴露任意 evaluate，避免扩大权限；必要时只能依据宿主文档做只读 DOM 检查，不读凭据、页面存储或网络数据。

也曾截图用于查看浮层，但**没有用像素坐标点击**。新版无需截图即可运行上述 DOM 流程。

## UI 树是什么意思

实际读到的是 `playwright.domSnapshot()` 输出的页面 DOM/语义结构，包含 generic、textbox、button 等角色和页面文字。不是 macOS 辅助功能树，也不是手写 OCR。`playwright` 是宿主 API 的命名空间；这份 skill 没有安装 Playwright 包，没有 `launch()`、`connectOverCDP()` 或自启动 Chrome 的脚本。但这不能证明宿主内部不使用调试机制。

## 调试红线的事实边界

- 我没有运行开启远程调试端口的命令，没有重启带调试参数的 Chrome。
- 宿主连接报过 `Debugger unattached`，这是不能忽略的事实。
- 当前没有足够证据确定其内部是否使用 `chrome.debugger`/CDP，也没有宿主内部实现可供本 skill 禁止。
- 因此，新版**不能被标为满足“底层绝无调试会话”的合规实现**。抖音来客的该项用户硬约束仍有效，未证实之前不再次接管目标页。用户要求按实际方式写 skill，不等于撤销这一红线。
- 不向用户要求开发者模式、不教绕过账号限制，不把能读 DOM 解释成可以安全附着 debugger。

官方 OpenAI 文档描述 Chrome 控制通过浏览器扩展使用已登录浏览器；该公开说明没有建立本会话内部“绝无调试”的结论。见 [Using your computer and browser](https://developers.openai.com/training/walkthroughs/using-your-computer-and-browser)。本 skill 的具体 API 来源是当次工具返回的运行时文档与实际调用记录，不是对所有 Codex 版本的通用接口承诺。

## 接收方怎样调用

1. 具备同样 `mcp__cua_repl.js` 工具的 agent，先读 `SKILL.md` 并核对站点限制；不满足调试红线时停止，不接管站点。
2. 在允许使用现有连接的环境，按 skill 顺序分别调用发现、选浏览器、枚举、接管、DOM 快照。
3. 阅读 `scripts/runtime-helpers.repl.js`，将完整声明作为后续 `mcp__cua_repl.js` 调用内容执行。不要用 shell/node 执行该文件；其中的宿主对象仅存在于 REPL。
4. 在最新 DOM 指引下使用辅助函数，例如：

   ```javascript
   nodeRepl.write(await existingChromeUI.inspect(liveTab,{by:'text',value:'导出评价'}));
   ```

   确认当前公司、日期、控件语义且用户授权后：

   ```javascript
   nodeRepl.write(await existingChromeUI.clickReviewed(liveTab,
     {by:'text',value:'导出评价'},
     {kind:'export',reviewed:true}));
   ```

   `reviewed:true` 是 agent 的核验记录，不能代替用户授权或解除调试约束。辅助函数的拒绝词检查不是网站后端写入防火墙。必须先阅读实际 DOM，不能因为一个参数就点击未知按钮。
5. 平台显示正确任务生成成功后，按当前 DOM 唯一定位其下载按钮，使用 `downloadReviewed`。下载函数是当时 API 文档中可用的路线，未在此次商户页面完成实际验证。
6. 下载完成还需通过本机文件工具确认路径存在、大小及目标文件内容，再交付。

## 外部程序调用的限制

这份封装没有本地 HTTP 服务或独立 Chrome CLI；原来的实际方法本来就依赖 Codex 宿主工具。外部程序如果没有同一宿主工具和连接，不能仅凭复制 skill 来接管 Chrome。

不能为满足“外部调用”形式而发明未公开端点、导出宿主凭据或把工具内部连接转成私有代理。若以后宿主提供正式外部接口，可按其正式文档另做适配；那是独立工作，不冒充当前已实现能力。

## 安装和卸载

在本交付目录执行：

```sh
python3 scripts/install.py
```

只创建 `~/.codex/skills/control-existing-chrome-ui`。可用 `--dest /指定目录/control-existing-chrome-ui` 改安装位置；已有目录拒绝覆盖。没有任何 Chrome 安装/授权命令，没有本地服务、自启动项或密钥。

卸载仅需从文件管理器移走安装的 skill 目录，不涉及 Chrome。已经存在的宿主 Chrome 连接由产品管理，本 skill 不安装、不卸载或改其权限。
